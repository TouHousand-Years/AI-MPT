# 决定统一音频包络与资源上限

Parent: ../map.md
Type: grilling
Status: open
Blocked by: 01, 02, 03

## Question

综合两条原生生成路径和候选提供商能力，首版统一音频包络应采用什么 PCM/容器格式、采样率、位深、声道、响度/归一化规则、时长与字节上限、哈希规范和安全元数据；硬上限由应用、Harness 与提供商适配器如何共同收紧而不能被 MCP 调用者放宽？

## Completion evidence

- 冻结版本化 envelope schema 和至少两个规范测试向量，覆盖音色与乐段路径及 `audioContentHash` 计算。
- 区分提供商无关的不变量与由候选能力决定的格式/上限，记录被拒替代方案及理由。
- 用限制矩阵说明应用、Harness 与适配器各自校验什么，并验证调用者只能收紧、不能放宽硬上限。
- 明确音频只由原生侧产生，人工与 AI 引用同一内容身份，包络不携带项目路径、用户名或凭据。
