# Agent 跨 Pattern 编辑与审批

Label: triage
Source: user request, 2026-09-13.

允许 Agent 读取当前 Sequence 的 Pattern 顺序，申请切换目标，并逐个 Pattern 编辑、提交。每次只保留一个 Pattern 候选，每份提交和一次 Undo 都仅涉及一个 Pattern。

- 新增 get_pattern_order：返回当前 Sequence 标识、按 Order 索引排列的条目，以及有效 Pattern 的编号、名称和行数。保留重复引用、跳过与停止标记，并列出未被当前 Sequence 引用的有效 Pattern。读取不申请写占用。
- 新增 switch_pattern，接受目标 pattern 和可选会话令牌：已有占用必须提供有效令牌；无会话时可直接申请切换，获批后建立会话。
- 有未提交修改或待审核提案时拒绝切换，要求先应用、拒绝或取消当前工作，不隐式提交或丢弃。
- 批准后重新捕获目标 Pattern 的基线及依赖，授权全部行和通道，返回会话令牌与目标上下文。后续编辑仍只能操作绑定的 Pattern。
- 同步更新 Patterns 页显示，清除旧选区，不修改 Sequence、Order 内容或播放位置。重复 Order 引用仍编辑同一 Pattern，返回信息明确提示这一关系。
- 切换到当前绑定 Pattern 为无操作；不存在的 Pattern 拒绝。人工导航不改变 Agent 绑定目标。
- Sidecar 继续固定活动会话的文档连接，并识别切换成功返回的会话令牌。
- 在现有 AI / MCP 页增加“批准切换 Pattern”和“拒绝切换 Pattern”，显示源、目标编号与名称，以及整 Pattern 授权范围。
- 将待批准状态区分为范围扩展和 Pattern 切换，复用原调用等待机制。等待期间暂停空闲超时；拒绝保持原绑定，强制释放、断连或关闭文档终止等待。批准时重新验证目标和会话。
- 增加持久化选项“总是允许切换 Pattern”和“总是接受提交”，默认关闭，与现有范围扩展设置独立。
- “总是允许切换 Pattern”自动批准后续合法请求；开启时若已有切换请求等待，则立即尝试批准。
- “总是接受提交”使后续 handoff_for_review 冻结后立即调用现有原子应用路径；开启时也立即尝试应用已有待审核提案。
- 自动应用保留修订、单元格验证和 Undo 准备。失败时文档不变，提案保留供处理，返回明确失败原因及提案仍待处理的状态；成功返回已应用状态。手动审核路径继续可用。
- 调整面板布局，保证设置、审批状态和审核按钮可见。

验证：顺序重复/跳过/停止/未引用/Sequence 变化/无效引用；切换手动批准/拒绝/自动批准/同目标/无效目标/旧令牌/其他连接占用/等待中的释放断连关闭；未提交候选与待审核提案阻止切换，处理后可编辑下一 Pattern，提交与 Undo 隔离；自动接受默认手动、开启应用已有提案、后续自动应用、stale、空提案、Undo 准备失败。扩展 C++ 能力、Sidecar 协议与原生集成测试；实机验证 Patterns 同步、播放位置与布局。

更新用户指南、Sidecar 说明、仓库内 Pattern MCP 技能指引。沿用零基索引；不新增 Pattern 创建、Order 重排、跨 Sequence 切换或多 Pattern 草稿。
